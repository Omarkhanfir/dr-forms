# Handoff

## Current progress

- The current pacing is Wave 1 -> Question 1 -> Reward -> Wave 2 -> Question 2 -> Reward -> Wave 3 -> Question 3 -> Reward -> Victory. The former 10-second trigger is removed. This prototype validates three waves and three separate content entries (three options each); future creator interval settings remain in scope for the platform.
- Question/reward state lives in `PrototypeQuestions`; the wave controller owns clear/break/Victory transitions and resolves them after combat updates, with defeat taking precedence in a same-frame tie. Every clear waits for its matching question, exactly one submission/reward, and Continue. Victory cannot occur before three answers. Equal +10 damage rewards and hidden correctness feedback remain the defaults.
- Question opening disables/clears gameplay input, freezes scaled time, and waits for all mouse buttons/touches and Enter/Space to release before a configurable 0.5-second guard. `PrototypeDeliberateButton` requires a fresh down in the current screen generation and rejects double-click/held-key UI submissions. Selection changes do not submit; Submit Answer stays disabled until selection. Reward Continue is separately guarded. Focus cancellation invalidates pending gestures and freezes the scaled game clock, preserving cooldowns and break time; combat resume clears input and retains the neutral/fresh-pointer gate.
- UI uses an opaque safe-area screen, wrapping text, dynamically sized options inside a clipped scrolling viewport, visible selection/focus, and fixed Submit/Continue actions. Keyboard directional navigation reveals focused options in the scroll viewport. Defeat and Victory use the existing ending overlay with Retry / New Run labels; questions/rewards close before ending transitions.
- Defeat Retry reloads scene transients and restores health, spawning only the unfinished wave. Completed-wave count, submitted answers and earned damage remain in memory; completed questions/rewards are never repeated. Victory New Run resets that state and base damage. Browser refresh/close/application restart does not persist progress.
- Three waves retain 2/3/4 chasers, the 3-second post-reward break, safe spawn clearance and inactive original enemy template. The separate practice target does not count toward wave completion. Arena/controls/combat defaults, original assets/GUIDs, packages and recovery files are preserved.

- `docs/PROJECT.md` defines Dr.forms; pricing and hosting remain undecided. Follow `AGENTS.md` for workflow.
- Unity 6000.6.4f1, Input System 1.20.0, and all package versions are unchanged. WebVerification, its source/materials/helper, the original scene, and the default build scene list are preserved.
- GamePrototype retains its arena, floor/wall colliders, capsule CharacterController, and smooth fixed-angle camera following. Keyboard movement has been replaced with the requested desktop/touch controls.
- Desktop: moving the mouse over the arena floor samples a world destination without holding a button. A stationary cursor retains that target as the camera follows. A three-pixel pointer dead band, 0.12-unit arrival radius, hysteresis, slowdown, and step cap prevent destination jitter/overshoot. Left-click in the game triggers attack input; UI hover/clicks block world input.
- Phones/tablets: a safe-area-aware left-thumb joystick provides camera-relative analog movement; the right-thumb attack button tracks an independent touch. Releasing either finger does not disrupt the other control. UI uses the installed Input System's multi-pointer module.
- Basic ranged combat is implemented: desktop left-click / touch Attack fires one visible projectile at the nearest living target in range. Successful shots retain the 0.25-second player/HUD flash. Held input does not repeat; cooldown and no-target/out-of-range presses fire nothing. Movement and independent touch controls are preserved.
- `PrototypeCombat` on Prototype Player exposes Inspector settings for damage (25), range (6), cooldown (0.25 seconds), and projectile speed (10). The stationary target at (0, 1, 4) has configurable maximum health (100), a camera-facing health bar/numeric label, and disappears at zero. Damage occurs once on projectile arrival. Combat feedback includes a muzzle flash, short projectile trail, target hit flash, smoothly draining health bar, and short defeat burst. The stationary target is preserved alongside the wave chasers. Local sample questions are now integrated through `PrototypeQuestions`.
- The blue capsule chaser template retains its original (-4, 1, -4) position but is inactive; only wave clones chase the player using a CharacterController and take damage through the existing target/combat-effects component. Inspector settings: speed 2.5 units/second, contact damage 20, contact cooldown 1 second, contact distance 1.1 units; enemy maximum health is 100. Direct pursuit stops near the player and uses arena/floor collisions; it does not include obstacle pathfinding.
- Player maximum health (100) is Inspector-configurable. A safe-area HUD health bar/numeric label updates on damage; zero health freezes the clock, blocks gameplay, cancels projectiles, and shows a blocking DEFEATED overlay with Retry.
- Retry / New Run reload GamePrototype, restoring health, camera, combat/contact counters and cooldowns, and clearing all projectiles, effects and old control owners. Retry spawns the unfinished wave with earlier upgrades; New Run spawns wave one with base stats. Held buttons/touches must reach a neutral frame; then fresh input is accepted. A stationary desktop cursor cannot resume an old destination, but a new click can fire without moving the cursor. An Editor-only scene-path reload supports the prototype without changing the default build scene list.
- The WebGL canvas bridge cancels input on blur/hidden tabs/pointer cancellation. Desktop pointer exit and a joystick thumb dragged outside the game stop movement. Stale destinations/touches do not resume after cancellation.
